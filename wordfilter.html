Using the filter

Run /wordfilter add pattern:<text> for one pattern. For a list, use /wordfilter bulk-add patterns_json:<array>; remove several with /wordfilter bulk-delete. JSON import adds patterns without replacing the current list. Discord limits each JSON option to 6,000 characters, so split larger exports into batches; the server stores up to 100 patterns total.

Plain text is matched as a whole word or phrase, without case sensitivity. If a pattern contains regex syntax such as *, \, [ ], or parentheses, the bot treats it as a Java regular expression.

Regex examples:

\b(?:badword|awfulword)\b free\s+(?:gift|nitro) https?://(?:www\.)?example\.com(?:/\S*)?

Patterns are case-insensitive. A pattern must not match an empty string. The live preview uses your browser's regular-expression engine; the bot uses Java regex, so test complex expressions in Discord before enabling them.

Custom warning messages

Set the text sent for a word-filter match with /wordfilter message template:<text>. Use these placeholders:

  • {filter} — the configured pattern that matched.
  • {user} — the member mention.
  • {segment} — the matched text from the message.

For example: /wordfilter message template:{user}, “{segment}” matched the filter {filter}. Reset it with /wordfilter message-reset. Repeated filtered messages use the anti-spam message limit, time window, and punishment setting even when anti-spam detection is disabled.

How the bot reads patterns

A pattern with no regex metacharacters is treated as plain text: it matches a whole word or phrase, without case sensitivity. For example, bad word matches that phrase but not bad wording. If the pattern contains regex syntax such as a backslash, dot, quantifier, parenthesis, or character set, it is treated as a raw Java regex. Raw regexes do not get automatic word boundaries, so add them yourself when needed.

The bot rejects patterns that match an empty string, allows up to 100 patterns per server, and limits each pattern to 250 characters. Regex matching is case-insensitive, with Unicode-aware character classes.

1. Literal text and escaping

Most characters match themselves. Regex metacharacters have special meanings; escape one with a backslash to match it literally. A dot means “any character,” while \. means an actual period. The slash character / does not need escaping because patterns are entered without slash delimiters.

Use \Qtext\E in Java regex to quote a block as literal text. A plain pattern such as free gift is already treated literally by the bot.

2. Character shortcuts and sets

SyntaxMeaningExample
\s / \SWhitespace / non-whitespace.free\s+gift
\w / \WWord character / non-word character. With the bot's Unicode mode, word characters include Unicode letters, marks, digits, and connector characters such as underscore.\w{3,}
\d / \DUnicode decimal digit / any character that is not a decimal digit.\d{4}
.Any character except a line terminator by default.free.*gift
[abc]One character from the set.gr[ae]y matches “gray” or “grey”.
[a-z]One character in a range.[A-F0-9]
[^abc]One character not in the set.[^0-9]+
\p{L} / \p{N}Unicode letter / Unicode number categories.\p{L}+
\t, \n, \r, \fTab, line feed, carriage return, and form feed.first\nsecond
\RAny Unicode line-break sequence (Java-specific).first\Rsecond

Inside a character set, most metacharacters lose their special meaning. A hyphen makes a range when placed between characters; put it first or last, or escape it, to match a literal hyphen.

3. Repetition and optional text

SyntaxMeaningExample
?Zero or one occurrence.colou?r matches “color” or “colour”.
*Zero or more occurrences.ab*c
+One or more occurrences.\s+
{n}Exactly n occurrences.\d{4}
{n,}At least n occurrences.a{2,}
{n,m}Between n and m occurrences.\d{2,5}
*?, +?, ??Lazy forms: match as little as possible while still allowing the rest of the pattern to match.<.+?>
*+, ++, ?+Possessive forms (Java-specific): do not give characters back to later parts of the pattern.\d++

Quantifiers apply to the character or group immediately before them. For example, (ab)+ repeats the pair; ab+ repeats only the b.

4. Groups and alternatives

Parentheses group parts of a pattern. A normal group also captures its matched text; (?:...) groups without capturing. The vertical bar means “or,” and its scope is controlled by groups.

free\s+(?:gift|nitro)

This matches “free gift” or “free nitro”. A named capture uses (?<name>...); numbered captures can be referenced with \1, while named captures can be referenced with \k<name>. Captures are usually unnecessary for a word filter unless a later part of the same pattern needs to refer back to them.

5. Boundaries and anchors

SyntaxMeaning
\b / \BWord boundary / position that is not a word boundary.
^ / $Start / end of the input. Inline multiline mode can make them work at line boundaries too.
\A / \zAbsolute start / absolute end of the input (Java syntax).
\ZEnd of input, allowing a final line terminator (Java syntax).

Because regex patterns are raw, bad can match inside badminton. Use \bbad\b to require word boundaries, or use the plain pattern bad to get the bot's automatic whole-word behavior.

6. Lookarounds

Lookarounds check nearby text without including that text in the matched segment:

  • (?=text) — positive lookahead: the next text must match.
  • (?!text) — negative lookahead: the next text must not match.
  • (?<=text) — positive lookbehind: the previous text must match.
  • (?<!text) — negative lookbehind: the previous text must not match.

Example: free(?!\s+trial) matches “free” unless it is followed by “trial”. Java lookbehind has restrictions on the expressions it can contain; test it with the bot before relying on it.

7. Inline flags

Flags change how a regex is interpreted. Put an inline flag near the start, for example (?s)first.*last to let a dot cross line breaks, or (?m)^word$ to anchor to each line. Java also supports (?x) for whitespace and comments in a regex, and scoped flags such as (?s:...).

The bot already applies case-insensitive Unicode matching, so (?i) is normally redundant. A scoped flag such as (?-i:ABC) can turn case-insensitive matching off for one group. The browser preview uses JavaScript regexes while the bot uses Java regexes; Java-only syntax (for example \R, \A, possessive quantifiers, and \Q...\E) may not work in the preview. The preview also cannot prove how the bot will behave, so test complex patterns in Discord.

8. Practical examples

GoalPattern
Free gift or nitro offers, allowing extra spaces or line breaksfree\s+(?:gift|nitro)
Whole-word “bad” or “awful”\b(?:bad|awful)\b
Four to six digits as a whole token\b\d{4,6}\b
HTTP or HTTPS links to example.comhttps?://(?:www\.)?example\.com(?:/\S*)?
Several spaces or tabs between two wordsfirst\s+second

Keep patterns specific. Broad expressions such as .* can match too much, and nested repetition such as (a+)+ can be expensive to evaluate. Test the exact phrases you want to catch and a few similar phrases you want to allow.

Self-Hosting Guide

Run your own Ammonite instance and manage its configuration and data.

Before You Begin

  • Git, Java 17 or newer and Apache Maven.
  • A Discord application with a bot account and its token.
  • The project includes a native library for Linux x86-64. Other operating systems or processor architectures may need a matching native dependency.
  • Node.js 20 or newer is optional. It is needed only for the YouTube recovery sidecar.

Self-hosting runs a separate bot instance with its own configuration and local data; it does not copy data from another Ammonite instance.

Build and Configure

  • Clone the Ammonite source repository and change into the project directory: 
    git clone https://github.com/itz-winter/kelpyyium-bot.git
cd kelpyyium-bot
  • In the Discord Developer Portal, create an application and bot, then copy its token. Enable the Server Members, Message Content and Presence privileged gateway intents. Invite the bot to your server with the bot and applications.commands scopes and the permissions it needs; see the Setup Guide.
  • Build the executable JAR from the project directory: 
    mvn clean package
    Maven creates target/discord-server-bot-1.0.0.jar.
  • Start the bot from the project directory: 
    java -jar target/discord-server-bot-1.0.0.jar
    If config.json does not exist, the first launch creates it with a placeholder token that cannot authenticate.
  • Open config.json in the project directory, set bot_token to your bot token, save the file, then run the start command again. Keep the token private and never commit it to source control.
Optional music fallbackTo enable the YouTube recovery sidecar, install Node.js 20 or newer, then run npm ci in the music-sidecar directory. The bot itself can run without this sidecar.

Keep It Running

  • Run the JAR from the project directory so the bot can find config.json, data/, logs/ and the optional sidecar.
  • Keep the process running with your preferred service manager, and check logs/ if the bot does not come online.
  • Back up config.json and the bot's data regularly. Store backups securely because configuration may contain secrets.

For server configuration after startup, see the Setup Guide. For command and permission details, see the Command Reference and Permissions.

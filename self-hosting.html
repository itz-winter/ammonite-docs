Self-Hosting Guide

Run your own Ammonite instance and manage its configuration and data.

Before You Begin

  • Java 17 or newer.
  • A Discord application with a bot account and its token.
  • The downloadable release includes a native library for Linux x86-64. Other operating systems or processor architectures may need a matching release.

Self-hosting runs a separate bot instance with its own configuration and local data; it does not copy data from another Ammonite instance.

Build and Configure

  • Create a folder for the bot on your host and download the latest Ammonite release into it. Save the file as ammonite.jar.
  • In the Discord Developer Portal, create an application and bot, then copy its token. Enable the Server Members, Message Content and Presence privileged gateway intents. Invite the bot to your server with the bot and applications.commands scopes and the permissions it needs; see the Setup Guide.
  • Open a terminal in the folder containing ammonite.jar and start the bot: 
    java -jar ammonite.jar
    On its first launch, Ammonite creates config.json and the required data folders. Stop the process after the configuration file has been created.
  • Open config.json, set bot_token to your bot token, and save the file. The optional bot_name setting changes the name shown in the startup banner and defaults to Ammonite. Keep the token private.
  • Start the bot again with java -jar ammonite.jar. Keep it running to keep the bot online.
Music fallbackThe optional YouTube recovery sidecar requires Node.js 20 or newer and separate sidecar files in a music-sidecar folder beside the JAR. The bot can run without the sidecar.

Optional Commands and Response Lines

Optional slash-command features are disabled by default. Set the matching flags in config.json and restart Ammonite to enable them.

  • custom_command_names_enabled lets you rename /echo, /join, /leave, /rpc and /statusmsg through command_names.
  • custom_command_aliases_enabled registers additional names from command_aliases.
  • custom_commands_enabled registers commands from the custom_commands map.
  • custom_command_actions_enabled allows those commands to pin or react to configured message IDs.
  • custom_lines_enabled uses custom join, leave and action response lines from custom_lines. Each action can also define success_line and failure_line.
{
  "custom_command_names_enabled": false,
  "custom_command_aliases_enabled": false,
  "custom_commands_enabled": false,
  "custom_command_actions_enabled": false,
  "custom_lines_enabled": false,
  "command_names": {
    "echo": "echo", "join": "join", "leave": "leave", "rpc": "rpc", "status": "statusmsg"
  },
  "command_aliases": {
    "echo": ["talk", "say"], "join": ["join-us"], "leave": ["leave-us"],
    "rpc": [], "status": ["set-status-message"]
  },
  "custom_commands": {
    "pin_notice": {
      "description": "Pin a configured notice",
      "response": "Working on it for {user}.",
      "actions": [
        {
          "type": "pin",
          "channel_id": "111111111111111111",
          "message_id": "222222222222222222",
          "success_line": "Pinned {message_id}.",
          "failure_line": "Could not pin {message_id}."
        },
        {
          "type": "react",
          "channel_id": "111111111111111111",
          "message_id": "222222222222222222",
          "emoji": "✅",
          "success_line": "Added {emoji} to {message_id}."
        }
      ]
    }
  },
  "custom_lines": {
    "join_success": ["Connected to {channel_name}."],
    "leave_success": ["I left the voice channel."],
    "pin_success": ["Pinned {message_id}."],
    "react_failure": ["Could not react to {message_id}."]
  }
}

Replace the example IDs before enabling actions. Omit channel_id to use the channel where the slash command was run. The target must be in the same server. The person running an action needs View Channel and Manage Messages in the target channel. Ammonite needs View Channel and Read Message History to fetch the message, plus Manage Messages to pin or Add Reactions to react. Action commands reply privately. Templates support {message_id}, {channel_id}, {emoji}, {user}, {username}, {channel}, {channel_name} and {server}.

The names and aliases shown above are prefilled examples. They remain inactive until their respective flags are enabled.

Linux systemd Service

The example systemd unit file starts the Java JAR directly and restarts it if it exits. These commands use /opt/ammonite as the install folder; adjust the paths if you choose another location. If Java is not installed at /usr/bin/java, update ExecStart in the unit file to the path returned by command -v java.

  1. Create a dedicated service account and install the JAR: 
    sudo useradd --system --user-group --no-create-home --home-dir /opt/ammonite --shell /usr/sbin/nologin ammonite
sudo install -d -o ammonite -g ammonite -m 0750 /opt/ammonite
sudo install -o ammonite -g ammonite -m 0644 /path/to/ammonite.jar /opt/ammonite/ammonite.jar
  2. Run Ammonite once to create its configuration and data folders. Stop it with Ctrl+C after config.json appears: 
    sudo -u ammonite sh -c 'cd /opt/ammonite && /usr/bin/java -jar ammonite.jar'
  3. Set bot_token in the generated config, then restrict access to it: 
    sudoedit /opt/ammonite/config.json
sudo chown ammonite:ammonite /opt/ammonite/config.json
sudo chmod 0600 /opt/ammonite/config.json
  4. Install and start the unit file: 
    sudo install -o root -g root -m 0644 ~/Downloads/ammonite.service /etc/systemd/system/ammonite.service
sudo systemctl daemon-reload
sudo systemctl enable --now ammonite.service
sudo systemctl status ammonite.service --no-pager

Follow service output with sudo journalctl -u ammonite.service -f. The application also writes logs under /opt/ammonite/logs/. The unit runs with /opt/ammonite as its working directory so the config, logs and relative data folders stay together.

After replacing the JAR, restart the service:

sudo install -o ammonite -g ammonite -m 0644 /path/to/ammonite.jar /opt/ammonite/ammonite.jar
sudo systemctl restart ammonite.service

Use the relevant command to stop the service, disable automatic startup, or enable it again:

sudo systemctl stop ammonite.service
sudo systemctl disable ammonite.service
sudo systemctl enable --now ammonite.service

Back up config.json and the data/ folder. The config contains the bot token.

Keep It Running

  • Always start the JAR from its bot folder so Ammonite can find config.json, data/ and logs/.
  • Keep the process running with your preferred service manager, and check logs/ if the bot does not come online.
  • Back up config.json and the bot's data regularly. Store backups securely because configuration may contain secrets.

For server configuration after startup, see the Setup Guide. For command and permission details, see the Command Reference and Permissions.
